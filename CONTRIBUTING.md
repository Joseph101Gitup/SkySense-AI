# Contributing to SkySense AI

Thank you for your interest in contributing to SkySense AI! This document provides guidelines for contributing to this project.

## How to Contribute

### 1. Reporting Bugs
- Search the issue tracker to see if the bug has already been reported.
- If not, create a new issue detailing:
  - The expected behavior vs. actual behavior.
  - Steps to reproduce the issue.
  - Relevant logs, screenshots, and environment details (OS, Python version, etc.).

### 2. Suggesting Enhancements
- Open an issue explaining your proposed feature or improvement.
- Describe the use case and why it would be beneficial to the project.

### 3. Submitting Pull Requests (PRs)
1. Fork the repository and create your branch from `main` (or the relevant development branch).
2. Follow standard coding guidelines for each module:
   - **Python**: Follow PEP 8 style guides.
   - **Android**: Follow official Android Kotlin/Java styling rules.
3. Ensure all tests pass.
4. Write clear, descriptive commit messages.
5. Submit a pull request and link it to the relevant issue.

## Development Workflow

### Branching Strategy
- Feature branches: `feature/feature-name`
- Bug fixes: `bugfix/issue-description`
- Documentation updates: `docs/doc-name`

### Commit Message Guidelines
We follow standard conventional commits:
- `feat`: A new feature
- `fix`: A bug fix
- `docs`: Documentation updates
- `style`: Formatting, missing semicolons, etc.
- `refactor`: Refactoring production code
- `test`: Adding missing tests or correcting existing tests
- `chore`: Updating build tasks, package manager configs, etc.

## Code of Conduct
Please be respectful and collaborative in all communication and code reviews.
