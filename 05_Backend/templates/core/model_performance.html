SCIENTIFIC DISCLOSURE & ENGINEERING SPECIFICATION

Methodology

End-to-end technical methodology for ground-based cloud-image rainfall prediction.

Critical Model Scope Clarification

The SKYsense AI deep learning model is engineered to predict rainfall likelihood categories (Low_to_Medium_Rain, Medium_to_Heavy_Rain, No_to_Low_Rain) from ground-based cloud photography. This model is NOT a cloud-type or cloud-genus classifier. The 11 standard WMO cloud genera from the source CCSN dataset were meteorologically mapped and aggregated into 3 rainfall potential regimes to solve an operational precipitation estimation objective.

1 Dataset Architecture

The system utilizes the Cirrus-Cumulus-Stratus-Nimbus (CCSN) ground-based sky image database comprising 2,543 verified RGB images. These 11 cloud genera were scientifically mapped into 3 consolidated rainfall regimes:

  • Low to Medium Rain (1,004 images): Altostratus, Stratocumulus, Stratus, Nimbostratus.
  • Medium to Heavy Rain (624 images): Cumulonimbus, mature Cumulus, Cirrostratus thick.
  • No to Low Rain (915 images): Cirrus, Cirrostratus, Cirrocumulus, Altocumulus.

2 Preprocessing & Augmentation

Specimen images undergo standardized image pipeline transformations:

  • Spatial Rescaling: Interpolated to 256 × 256 pixels maintaining 3 RGB channels.
  • Normalization: Pixel intensity scaled from [0, 255] to [0.0, 1.0] using 1/255.0 rescale.
  • Stratified Split: 70% Train (1,779), 15% Validation (383), 15% Test (381).
  • Training Augmentation: Random rotations (±25°), horizontal flips, and width/height shifts (±20%) applied strictly during training to improve generalized cloud invariance.

3 Transfer Learning Paradigm

Training deep neural networks from scratch on limited meteorological datasets often induces severe overfitting due to diffuse visual textures. We exploit transfer learning by adopting weights pre-trained on the ImageNet dataset (1.4 million images). The network acts as a robust hierarchical feature extractor, capturing fundamental visual representations (edges, gradient orientations, textures) before adapting to meteorological features.

4 Xception Backbone

The architecture employs Xception (Extreme Inception), replacing standard Inception modules with depthwise separable convolutions. Features include:

  • 36 Convolutional Stages structured into 14 modules with residual shortcut connections.
  • Separation of Cross-Channel & Spatial Correlations, vastly reducing parameter overhead while maximizing representational expressiveness (20.8M parameters).
  • Custom Head: GlobalAveragePooling2D followed by a 40% Dropout stage and a 3-unit Dense layer with Softmax activation.

5 Phase 1 Training

In the initial training phase, all convolutional weights of the pre-trained Xception base are frozen. Only the new classification head (GlobalAveragePooling2D, Dropout, and output Dense layer) is trained using:

  • Optimizer: Adam (learning rate = 1e-3, β1 = 0.9, β2 = 0.999).
  • Loss Function: Categorical Cross-Entropy across the 3 rainfall classes.
  • Batch Size: 32 specimens per gradient update step.

6 Phase 2 Fine-Tuning

To adapt higher-level convolutional representations to cloud optical densities and atmospheric moisture gradients, the upper blocks of the Xception backbone are unfrozen. A substantially reduced learning rate (1e-5) is utilized alongside EarlyStopping and ModelCheckpoint callbacks, allowing delicate adaptation of cloud boundary features without catastrophic forgetting of foundational ImageNet filters.

7 Empirical Evaluation Protocol

Evaluation was executed strictly on the isolated, held-out 381-sample test split that was completely unseen during both Phase 1 training and Phase 2 fine-tuning. The best checkpoint saved by validation loss monitoring was restored and evaluated to produce exact multi-class accuracy (58.27%), Macro Precision (61.23%), Macro Recall (55.74%), Macro F1 (56.60%), and the empirical confusion matrix.
